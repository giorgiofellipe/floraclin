```ts
const TERMINAL_STAGES = ['convertido', 'perdido'] as const

type MinimalProspect = { id: string; stage: string }

export async function findOrCreateProspect<P extends MinimalProspect>(opts: {
  lookup: () => Promise<P | null>
  createNew: () => Promise<P>
}): Promise<{ prospect: P; created: boolean }> {
  const existing = await opts.lookup()
  if (existing && !TERMINAL_STAGES.includes(existing.stage as typeof TERMINAL_STAGES[number])) {
    return { prospect: existing, created: false }
  }
  const fresh = await opts.createNew()
  return { prospect: fresh, created: true }
}
```

**Why injectable callbacks:** keeps the rule ("reuse active, recreate if missing or terminal") in one place, but leaves channel-specific lookup/creation queries to the callers. Create the webhook route mirroring `web/src/app/api/webhooks/whatsapp/route.ts` structure but with Instagram payload semantics.

**GET handler** — Meta hub verification using `process.env.INSTAGRAM_VERIFY_TOKEN`.

**POST handler:**
1. Read raw body, verify `X-Hub-Signature-256` against `process.env.META_APP_SECRET` using `verifyWebhookSignature` from `@/lib/meta-webhook`. Return 401 on mismatch.
2. Parse JSON. Expect `{ object: 'instagram', entry: [{ id, time, messaging: [...] }] }`.
3. For each entry, look up tenant by `entry.id == tenant.settings.instagram_business_account_id`. If not found, log warning and continue (respond 200 — Meta retries otherwise).
4. Defensive parsing: `entry.messaging` may be undefined; treat as `[]`. Each event may lack `sender` or `recipient`; guard against null and skip the event (log) if either is missing.
5. For each `messaging[]` event, **dispatch by event-key discriminator** (Meta sets exactly one of these per event):

   **`message` event** (`event.message` present, payload `{ mid, text?, attachments?, reply_to?, is_echo? }`):
   - **Echo detection:** if `event.message.is_echo === true`, skip this event for v1 (we already record outbound messages when we send them). Do NOT compare `sender.id` to the IG Business Account ID — that test fails in edge cases and `is_echo` is the canonical signal.
   - Dedupe by `mid` via `getMessageByMetaId`. If a row exists, skip.
   - The sender IGSID is `event.sender.id`. The recipient is our IG Business Account ID.
   - On first inbound from this IGSID (no conversation row exists yet): fire-and-forget profile enrichment via `getUserProfile`, then upsert conversation with returned name/handle/pic. If the call fails, the conversation is created anyway with null profile fields.
   - Determine `messageType`:
     - `'story_reply'` if `message.reply_to?.story` present — store `storyMediaUrl` and `storyId` from the reply_to object.
     - `'image' | 'video' | 'audio' | 'file'` if `attachments[]` present (use `attachments[0].type`). For mixed-attachment events, take the first attachment only in v1.
     - `'text'` otherwise.
   - For media: fire-and-forget `downloadAndStoreMedia(tenantId, attachment.payload.url, filename)` to Supabase; store the returned URL in `mediaUrl`. **Never store the IG CDN URL directly** — it expires in ~24h.
   - Call the shared helper with IG-flavored callbacks (note: import `getProspectByIgsid` from `@/db/queries/instagram` and `createNewProspect` from `@/db/queries/prospects`):
     ```ts
     const { prospect, created } = await findOrCreateProspect({
       lookup: () => getProspectByIgsid(tenantId, senderIgsid),
       createNew: () => createNewProspect({
         tenantId,
         source: 'instagram',
         igsid: senderIgsid,
         igHandle: profile.username ?? null,
         name: profile.name ?? null,
       }),
     })
     ```
   - Upsert conversation with `prospectId: prospect.id` and update `lastMessageAt` + `lastInboundAt`.
   - Create message row.
   - Increment `unreadCount`.
   - Fire-and-forget classification:
     ```ts
     const boundary = new Date(prospect.createdAt.getTime() - 60_000)
     const recent = await getRecentInboundBodies(conversation.id, 5, boundary)
     classifyProspectFromInbound({ tenantId, prospectId: prospect.id, prospectStage: prospect.stage, recentInboundBodies: recent })
       .catch((err) => console.error('IG classify failed', err))
     ```
     Note: explicit `new Date(... .getTime() - 60_000)` — do NOT use `Date - number` directly.
   - Push SSE events: `new_message`, `new_conversation` (if just created).

   **`reaction` event** (`event.reaction` present, payload `{ mid, action: 'react' | 'unreact', emoji? }`):
   - Resolve `reactsToMessageId` by looking up `reaction.mid` via `getMessageByMetaId`. If unknown (likely a reaction to a message we never stored), log and skip.
   - **`react` only in v1:** insert an `instagramMessages` row with `direction='inbound'`, `messageType='reaction'`, `metaMessageId=null`, `reactionEmoji=reaction.emoji`, `reactsToMessageId=resolvedId`, `body=null`.
   - **`unreact`:** log and skip in v1 (rows are not deleted; UI tolerates stale reaction rows). The complete unreact handling needs a `senderIgsid` column on reaction rows, which is deferred.
   - Push SSE `new_message` (UI re-renders the affected bubble's reaction badge).

   **`read` event** (`event.read` present, payload `{ mid?, watermark }`):
   - Call `markOutboundDeliveredUpToWatermark(conversationId, new Date(watermark), 'read')` (added in B2).
   - Push SSE `status_update`.

   **`delivery` event** (`event.delivery` present, payload `{ mids?: [...], watermark }`):
   - Same as read but with status `'delivered'`.

   **Unknown event** (`message`, `reaction`, `read`, `delivery` all absent — e.g. `postback`, `optin`, `account_linking`, `referral`): log the event keys and continue. Do not throw.

6. Always return 200 unless signature failed (401) or an unexpected DB error escaped the try/catch (500 — Meta will retry, which is safe due to `metaMessageId` dedup and `ON CONFLICT` on conversations).

**Constraints:**
- This file is yours alone. Do not modify B2's queries to add the watermark helper — either inline a tiny update query in this file, or call `updateMessageStatus` once per message.
- All Meta-API client calls go through `@/lib/instagram`.

```ts
function extractVariableKeys(body: string): string[] {
  const re = /\{\{(\w+)\}\}/g
  const keys = new Set<string>()
  let match: RegExpExecArray | null
  while ((match = re.exec(body)) !== null) keys.add(match[1])
  return Array.from(keys)
}
```

## Notes on the design that did not fit into tasks

- **The 60s classification boundary**: passed through from `findOrCreateProspect`'s return into the call to `getRecentInboundBodies`. The webhook (C1) is responsible for applying the boundary (`prospect.createdAt - 60s`) when building the `since` argument.
- **CDN media URL expiry**: IG inbound attachment URLs expire in ~24h. The webhook (C1) must download immediately via `downloadAndStoreMedia` and store the Supabase URL — never store the IG CDN URL in `mediaUrl`.
- **Race on profile fetch**: profile enrichment is fire-and-forget. If it lands after the conversation row is created, the row is updated with profile fields. If it never lands (private profile), the row stays with null fields — the UI handles this with "Usuário do Instagram" fallback (handled by `conversation-list.tsx` and `chat-panel.tsx`).
